# Floating papers use a document tray, not HUD toggles

**Status:** accepted  
**Date:** 2026-11-23  
**Context:** Phase 2D Parts 5–6 put Orders / Lesson / Province / Legend (and campaign Log, Chief of Staff, OHL) in parchment `FloatingWindow`s toggled from the HUD. Raymond’s Part 7 brief asked for documents-on-a-table UX: press–drag–release without a second click to drop, no vertical grow while dragging Orders, and a bottom tray where stowed papers sit as tabs.  
**Decision:** Remove window-open buttons from the top bar (title, date, and lesson/campaign goal stay). Host a parchment **document tray** (`components/document-tray.tsx`, `lib/ui/document-tray.ts`) along the bottom of the map stage. Stowed papers are tray tabs (real `<button>`s); click or drag-up restores; Stow control, Escape, or drag-down into the tray band returns a paper. `FloatingWindow` uses pointer capture for press–drag–release, locks height while dragging (optional resize handle for intentional grow/shrink), and clamps above the tray so papers cannot leave the stage. SessionStorage keeps open/position/tray state for the tab (`ostfront-windows-v1:campaign|teach`). Below `lg`, the tray is a bottom tab strip that swaps the stacked panel; `/teach` keeps Lesson (and Resolve) pinned so 390×844 QA stays green.  
**Consequences:** Demo-check and FEATURES treat `[data-testid=document-tray]` as the way to open papers; HUD no longer exposes `tab-orders` / `legend-toggle` on desktop. Engine, AI, API, and rules code are untouched. ADR 010/011 chrome and Lesson Resolve guarantees remain; this ADR only changes how papers are summoned and put away.
