Route **`/teach`**. Entry link on the scenario picker: `[data-testid=begin-teach]`. Campaign at **`/`** is unchanged.

On desktop (`lg+`, ≥1024px) `/teach` uses the same general’s-table shell as the campaign: full-width map, parchment HUD (title, date, `[data-testid=teach-goal]` — no window buttons), and draggable **Lesson** / **Orders** / **Province** / **Legend** papers (`[data-testid=teach-lesson-window]`, `[data-testid=teach-orders-window]`, `[data-testid=teach-province-window]`, `[data-testid=legend-window]`). Below `lg`, `h-dvh` stacked map → bounded Lesson (`[data-testid=teach-lesson-stack]`, Resolve in-viewport) → phone tray swapping Orders/Province/Legend — checked at 390×844.

### Province supply capacity (Sprint 3)

Each province has a **garrison supply capacity** (terrain base + depot bonus when controlled + 6× rail links). When fighting strength in the province exceeds capacity, **effective supply** scales as `networkSupply × min(1, capacity ÷ garrisonStrength)` — shown on the map Supply overlay and used for **attacks launched from** that province. **Defenders** still use the network line (`networkSupply`) in combat. **Your depot** still issues bulk rations: attacks launched from a depot you control never march below **72% of network supply**, even when the map shows overcrowding. Over-capacity provinces are spelled out in the fortnight **Chronicle** logistics.

**Converging attacks:** when any prong marches below supply **60**, the flank bonus is off and the pooled battle uses the **worst prong’s launch supply**, then scales it by `objective capacity ÷ (garrison + attackers)` when the combined column overfills the target. Well-fed prongs (all ≥ 60) still pool per-prong power with the normal flank multiplier (converging Lublin lesson).

### Fortify (Sprint 3)

**Fortify** costs **2 industry**, binds the province garrison for that fortnight (no move/attack), and raises fort **one level on the next fortnight** (max 3). While that order is queued, a drag or neighbour button onto another province is refused before release (`Digging in`) and draws no arrow. Capturing a fortified province reduces its fort by **one level** when control changes. Queue text still uses `[data-testid=fortify]`; the resolution log names IP spent and when entrenchments complete.

Trust: teaching resolve does **not** accept client `GameState` for grading. Full campaign **`/api/turn`** loads state from server Redis by `gameId` and accepts only `expectedTurn` and `orders` (server seed, #26).

## News cards (HOI4-style)

After each fortnight resolves, up to four headline cards (`[data-testid=news-card]`) appear in a viewport-level overlay (`[data-testid=news-card-overlay]`, `z-index` above sidebar and map). **Onward** (`[data-testid=news-onward]`) or Enter advances; **Skip all** (`[data-testid=news-skip-all]`) or Esc dismisses the queue. Images use `[data-testid=news-card-photo]` or `[data-testid=news-card-map]` (stylized vignette, not the live map). Encirclement beats (when the engine marks a pocket) trump duplicate city headlines; city and encirclement cards may show a factual `[data-testid=news-card-losses]` line (`Ours −N · Theirs −M`) from engine `BattleFacts`, not from lore text.

The map uses the full main height (no bottom Chronicle bar). Open **Log** (`[data-testid=chronicle-log-toggle]`) for the Chronicle (`[data-testid=chronicle-drawer]`; panel shell `[data-testid=mobile-chronicle-panel]`). On desktop (`lg+`, min-width 1024px) the campaign is a general's table: full-width map, no fixed 23rem right dock; **Orders**, **Province**, **Log**, **Legend**, **Chief of Staff**, and **Orders from OHL** are draggable parchment papers filed into / taken from `[data-testid=document-tray]` (HUD has no window buttons). Press–drag–release; drag onto the whole tray bar (or Escape) files a paper at the drop slot (insertion marker; including short OHL) — papers never paint behind the tray; drag and resting positions (and session restore) keep the header grip fully above the tray; release on the tray, below it, or at/past the viewport bottom files (pointer capture + cancel/lost-capture). Sideways tab drag or Alt+←/→ reorders; drag up or Enter restores (width/last size kept); tray order persists — no Stow buttons. Default-open after Begin: Orders, Legend (bottom-left), Orders from OHL. Below `lg`, the page is the phone viewport (`100dvh`, safe-area insets, no document scroll or pull-to-refresh). Stacked map + tray tab strip for Orders / OHL / Province / Chief of Staff; only that panel scrolls. A touch drag on an army chip queues an order and does not scroll the page; the map still pans and pinches when the gesture misses a unit. The map-corner Log control stays above the legend at every width from 640–1023px (no `sm:bottom-3` overlap). Inside `[data-testid=chronicle]`, the latest fortnight shows compact routine rows (`[data-testid=chronicle-routine]`) including short battle loss lines when `Resolution.battle` is present; **Details** (`[data-testid=chronicle-details-toggle]` → `[data-testid=chronicle-details]`) holds full narration, resolutions (`[data-testid=resolution-log]`), and logistics.

## Chief of Staff (campaign coach)

Phase **2E round 1**. The panel is `[data-testid=advisor-panel]` (tray tab `[data-testid=advisor-toggle]`). It is a **coach**, not an order clerk: it never issues orders and never shows Accept / Override / suggestion cards.

Ask with starters (`[data-testid=advisor-starter-plan|explain|review]`), or `[data-testid=advisor-input]` + `[data-testid=advisor-send]`. POST **`/api/advisor`** with `{ gameId, expectedTurn, messages, queuedOrders, selectedProvinceId? }` only — the server loads campaign state (and chronicle `log`) by `gameId` the same way `/api/turn` does. Replies land in `[data-testid=advisor-reply]`; optional follow-up in `[data-testid=advisor-follow-up]`. Highlights use province ids / interface ids (`[data-testid=advisor-highlights]`); the map paints them via `coachHighlightIds` on `[data-testid=war-map]` (`data-coach-highlights`). Speaks only when asked.

The coach discusses the player's queued arrows, the selected province, or chronicle battles (`BattleFacts` / routine log). Odds, supply, and results must come from the engine dispatch and records — not invented by the model. Style is a concise Chief of Staff voice (varied challenge phrasing; no stock “Do you accept…” / “The map shows…” templates; OHL wording for objectives; natural fort language, never “fort 1/2”): at most 2–3 sentences on every path (prompt + post-processing that drops whole sentences only — never mid-clause fragments), a question before any odds figure (never “About X:1…” first; a neutral decision question when nothing is queued or the figure is from the chronicle), one evidence fact with one map/UI highlight; post-battle asks for (or compares) a prediction without ledger noise, naming the chronicle fortnight of the most recent battle (or saying plainly when none exist). Odds quoted are the same `engagementOdds` / `combinedEngagementOdds` preview resolve uses after supply decay/capacity via `staffMap` — one figure, rounded to one decimal (or a whole number), phrased as “about X:1”, and “on this queued column” or “on the queued plan” only when an attack is queued (chronicle `at X:1 (roll N)` is left as written), plus “if the Russians don't reinforce” when that caveat is due (enemy moves are unknown; “before the dice” is scrubbed on every path; double-odds when/while comparisons are cut cleanly). The coach never claims an order was filed, noted, or queued, and a refusal asks the tradeoff instead of commanding “cancel the fortify” or a concrete attack. Player lines in the panel are labeled **You:** (no stray period). Rules/offline fallback matches that style (no key=value fields, no offline disclaimer). With `OPENAI_API_KEY` set, the coach calls OpenAI first (`OPENAI_MODEL`, default `gpt-6.1-terra`, reasoning effort `medium`) and uses the existing OpenRouter client only if that call times out, is rate-limited, or returns nothing usable; with neither key, the rules fallback answers. Queued arrows still expose structure on `[data-testid=queued-orders]` via `data-queued-order` for QA. The Orders from OHL goal line is semicolon-separated (`Take Lemberg by 13 June; Volhynia by 27 June; …`).

**Scenario eval harness** (prompt / coach quality, not a player feature): `npm run eval:coach` (`scripts/eval-coach.ts`, fixtures in `lib/gm/coach-eval/`). Fourteen engine-grounded boards cover under-supply traps, exposed flanks, clerk requests, pushback, sound concentric plans, fortify+attack queue conflicts, post-battle surprise reviews, illegal non-adjacent asks, reachability, captured-province and supply rejects, rejected chronicle rows, odds replies that must open with a question, and clerk refusals that must not prescribe a cancel. Layer 1 also rejects dangling odds clauses (including verbless trailing when/while subordinates and opening questions missing `?` or leading with the ratio) and residual dice / “combined-odds board” / “staff figures” jargon. `--offline` validates fixtures and Layer 1 hard rules against the rules/fallback path without API keys; with `OPENAI_API_KEY` or `LLM_API_KEY` set, Layer 2 grades pedagogy via the first configured provider (optional `EVAL_JUDGE_MODEL`). `--json <path>` writes a diffable report. CI covers fixtures + Layer 1 in `tests/coach-eval.test.ts` (no live LLM during `npm test`). The advisor send control uses a client abort timeout so a stalled `/api/advisor` call always clears busy and offers a retryable message.

## Game-master events

An event the engine rejects stays on the turn record with status `rejected`. The chronicle shows it as **Rejected**. It is not removed before the turn is resolved.

```bash

DEMO_URL=https://your-preview.vercel.app npm run demo-check
```
